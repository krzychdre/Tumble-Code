# UI step 5a: diffs (§2.7 of 2026-09-27_ui-modernization.md)

Branch `feat/ui-5a-diffs`, off `origin/main` (19d6d7dc7).

## What

- `webview-ui/src/utils/diffFolds.ts` (new, pure): `buildDiffRenderRows` flattens the parsed hunks into the rows
  to render. A run of more than six unchanged lines keeps three lines next to each neighbouring change and
  folds the rest into one row; a hunk separator or the hunk's start or end is a boundary (no context kept on
  that side). `countDiffStats` counts added and removed lines; `mergedLineNumber` picks the one number shown in
  the merged gutter (old number for a deletion, new number otherwise).
- `DiffView.tsx`: renders from those rows. Fold rows are real `<button>`s ("... N unchanged lines",
  i18n plural) that open the fold; the open folds reset when the diff source changes. Every line row carries
  the two split gutter cells (`diff-gutter-split`) plus one merged cell (`diff-gutter-merged`). The hunk
  separator text ("N hidden lines") moved to i18n. `rounded-md` dropped.
- `index.css`: `.diff-view` is an inline-size container; `@container (max-width: 399px)` hides the split
  gutters and shows the merged one. The `--vscode-diffEditor-*` colours are unchanged.
- `CodeAccordion.tsx` (the file header of every diff): sticky (`sticky top-0 z-10` with the editor background;
  the block drops `overflow-hidden`, which would otherwise become the sticky scroll box). For diffs it always
  shows `+N -M`: the payload's `diffStats` when present, otherwise counted from the diff (user-edit rows and
  older history had no counts). New "Open diff" icon button; the open-file control became a real `<button>`
  (both with i18n `aria-label`/`title`); the chevron is visible at 60% instead of `opacity-0` (§2.2 rule).
- `FileChangesPanel.tsx`: the per-file wrapper drops `rounded` and `overflow-hidden` (same sticky reason).
- Extension: new webview message `openDiff` (files domain): opens the patch as an untitled `diff` document in
  a preview tab (`vscode.workspace.openTextDocument({ content, language: "diff" })`), nothing written to disk.
- i18n: `chat:diffView.{unchangedLines,hiddenLines}` (plural, few/many for pl and ru), `openDiff`, `openFile`
  in all 18 locales.

## Why

In the sidebar two 45px line-number columns eat a sixth of the width; long unchanged runs push the actual
change out of the 300px body; the file header had no counts for user edits and no way to see the whole patch
at full width.

## Deviations

- "Open diff" opens the unified patch in an editor tab, not VS Code's side-by-side diff editor: the chat only
  has the patch (hunks with three lines of context), not both full file versions, so a side-by-side view cannot
  be built from it without re-reading files that may have changed since.
- A fold that would hide a single line is not created (an interior run of seven lines keeps 3 + 3 and would
  fold one line into a button of the same height).
- With the diffs the extension produces today (`createPrettyPatch`, context 3) jsdiff merges hunks whose gap
  is six lines or fewer, so interior folds mostly appear in diffs built with more context
  (`FileChangesPanel` uses `createTwoFilesPatch` with its default context) and in leading or trailing runs.
- The sticky header pins inside its own block: it stays visible while the expanded body (max 300px) scrolls
  past in the chat.
- `ChatRow.golden.json` regenerated: the file header markup changed (sticky classes, buttons, counts for user
  edits, chevron opacity).
