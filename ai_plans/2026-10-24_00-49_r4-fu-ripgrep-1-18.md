## Problem

`@vscode/ripgrep` 1.18 has no postinstall. The binary ships in an optional per-platform package
(`@vscode/ripgrep-<platform>-<arch>/bin/rg`), and the package exports `rgPath`, which resolves it with
`require.resolve`. Under pnpm that platform package sits next to `@vscode/ripgrep` in `node_modules/.pnpm`,
not under `apps/cli/node_modules`, so a lookup by path from the CLI root finds nothing: the extension's
`getBinPath` (appRoot = CLI root) and `tumble doctor` both failed, and `build.sh` and `cli-release.yml`
(`find -path "*/@vscode/ripgrep/bin/rg"`) would have shipped a release without `rg`.

## Change

- `resolveRipgrepPath()` (`apps/cli/src/lib/utils/ripgrep.ts`): an absolute `ROO_RIPGREP_PATH` (the release
  launcher's), else `rgPath` from a dynamic import of `@vscode/ripgrep`; undefined when the package is absent
  (the release does not install it) or has no build for the platform.
- `ExtensionHost.activate` sets `ROO_RIPGREP_PATH` to that path before the extension loads; the extension's
  `getBinPath` already reads the variable first. `src/services/ripgrep/index.ts` needs no change: its VS Code
  candidates already include the per-platform package layout of VS Code 1.130+.
- `tumble doctor` checks the same resolved binary instead of its own candidate list.
- `build.sh` and `cli-release.yml` take the binary from `rgPath` and copy it to `bin/rg` only (the launcher
  points `ROO_RIPGREP_PATH` there; the `node_modules/@vscode/ripgrep/bin` copy and its save and restore around
  `npm install` in `install.sh` are gone). The build fails when `rgPath` cannot be resolved, and the release
  workflow's tarball check requires `bin/rg`.
- The `allowBuilds` entry for the 1.17 postinstall, the `GITHUB_TOKEN` of the setup action (it served only that
  download) and the knip `ignoreDependencies` entry (the CLI now imports the package) go.

## Tests

- New `ripgrep.test.ts`: an absolute override wins; an unset or relative override falls back to the real
  platform package binary. `doctor.test.ts`: pass with the version line, fail on no binary and on a missing file,
  fail when it does not run.
- Mutation checks: accepting a relative override, ignoring the override, and dropping the existence check in
  `checkRipgrep` each turn one spec red. Removing the `setProcessEnv` in `ExtensionHost.activate` turns the CLI
  integration suite red ("Could not find ripgrep binary"), 4/4 again after restoring it.
- CLI integration suite 4/4 (was 0/4 with 1.18 before), `node apps/cli/dist/index.js doctor` passes with the
  platform package binary, CLI unit specs touched (336 passed), `src/services/ripgrep` specs 50 passed, CLI
  `tsc`, eslint, `pnpm knip`.
- `apps/cli/scripts/build.sh` locally: the tarball has `bin/rg` and no `node_modules`; unpacked and installed
  with `npm install --omit=dev`, `bin/tumble doctor` passes with `bin/rg`.
- `pnpm vsix` builds; the VSIX contains no ripgrep, as before: the extension uses the binary of the VS Code
  installation.
