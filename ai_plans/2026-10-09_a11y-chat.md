# Keyboard access in the chat: MCP call header, batch file rows, checkpoint menu

**Status:** done on `feat/a11y-chat` (round 2 of the frame-language work: keyboard access and labels).
**Related plans:** `2026-10-09_ui-frame-language.md` (its "Open items" listed these three gaps).

## Symptom

Three chat controls worked only with the mouse:

- The header of an MCP tool call (server > tool, status, chevron) expands and collapses the call, but it was a
  `div` with an `onClick`: Tab never reached it and Enter/Space did nothing; screen readers did not know it toggles.
- The per-file rows of a batch file-read request (`BatchFilePermission`) open the file on click, but were `div`s.
- The checkpoint row's menu (view diff, restore, jump to previous, more) was `display: none` unless the mouse
  hovered the row (component state `isHovering`). Hidden elements are not in the Tab order, so a keyboard user
  could never reach the menu.

## What changed

- `chat/McpExecution.tsx`: the header is now `<button type="button">` with `aria-expanded`, `w-full text-left`
  and the shared focus ring. Its children changed from `div` to `span` (a button may only hold phrasing content);
  they were already flex items, so the layout is the same. Same click handler.
- `chat/BatchFilePermission.tsx`: each row is the shared `ToolUseBlockHeader` (a `div` in `common/`, outside this
  branch's scope), so it got `role="button"`, `tabIndex={0}`, Enter/Space handling that calls the same `openFile`
  as the click, and the focus ring (negative offset, because the surrounding block clips with `overflow-hidden`).
  The accessible name is the row text (path and line snippet).
- `chat/BatchDiffApproval.tsx`: not changed. Its rows are `CodeAccordion` > `ToolBlock`, whose header already holds
  a real `<button>` with `aria-expanded`, and the open-diff / open-file actions are buttons too.
- `chat/checkpoints/CheckpointSaved.tsx`:
  - When the menu is not shown it is now `sr-only` (visually hidden, still in the Tab order) instead of `hidden`
    (`display: none`). Layout is unchanged: `sr-only` takes no space, exactly like `hidden` did.
  - New state `hasFocusWithin`. `onFocus` on the row sets it, but only for keyboard focus (`:focus-visible`), so a
    mouse click on a menu button does not pin the menu open after the pointer leaves: the mouse keeps its
    hover-only behaviour. `onBlur` clears it only when `relatedTarget` is outside the row, so moving between the
    menu's own buttons keeps it open. Focus moving into the portalled restore/more popover leaves the row, but the
    open popover already keeps the menu visible (`isPopoverOpen`), and Radix returns focus to the trigger on close.
  - `CheckpointMenu.tsx` needed no change: its controls are already `Button`s with aria-labels and the focus ring.

No i18n keys were added or changed.

## Tests (written first, each failed before the fix)

- `McpExecution.spec.tsx`: the header is a `BUTTON` with `type="button"`, `aria-expanded` false then true, the
  focus-ring class; Tab focuses it, Enter opens the details, Space closes them.
- `BatchFilePermission.spec.tsx`: one `role="button"` per file with `tabindex="0"`, the focus ring and an accessible
  name; Tab reaches the first row and Enter opens it, Tab to the second row and Space opens that one.
- `CheckpointSaved.spec.tsx`: with no hover, Tab lands on the first menu button and the menu shows; tabbing through
  the menu's buttons keeps it shown and reaches restore, jump and more; tabbing out of the row hides it. The
  existing hover tests now expect `sr-only` instead of `hidden` for the not-shown state.
- `ChatRow.golden-renders.spec.tsx`: golden regenerated with `UPDATE_GOLDEN=1`. The diff is only the expected
  markup change in four entries: the MCP header (two entries, `button` + `span`s + `aria-expanded`), the batch
  file-read rows (`role`, `tabindex`, focus classes) and `checkpoint_saved` (`sr-only` instead of `hidden`).
