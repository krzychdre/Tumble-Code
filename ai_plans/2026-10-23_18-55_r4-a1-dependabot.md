# R4 A1: Dependabot replaces the never-installed Renovate config

**Status:** done.
**Related plans:** `2026-10-23_17-20_maintenance-audit-round-4.md` (item A1, owner decision: Dependabot).
**Touched files:** `.github/dependabot.yml` (new), `renovate.json` (deleted).

## Problem

`renovate.json` described a good update policy, but the Renovate app was never installed on the repository, so no
update PR was ever opened and the dependency backlog grew by hand.

## Change

`.github/dependabot.yml` carries the same policy for the four ecosystems:

- `npm` at `/` (the pnpm workspace root; Dependabot reads `pnpm-workspace.yaml` and updates every workspace
  manifest and `pnpm-lock.yaml`), groups `type-definitions`, `dev-tooling`, `provider-sdks` and `webview-ui-libs`
  with the package lists of the Renovate groups. Renovate grouped webview packages by file; Dependabot groups only
  by name, so the webview group lists the webview libraries by name.
- `uv` for `self-hosted-cloudapi`, one group for the whole service.
- `docker` for `self-hosted-cloudapi/Dockerfile` (the base image is pinned by tag and digest).
- `github-actions` for `/` and the composite actions under `/.github/actions/*`, one group.

All entries run weekly on Monday at 05:00 Europe/Warsaw and ignore semver-major updates, which stay planned work.
The npm entry keeps Renovate's limit of six open PRs.

Not carried over: Renovate's `lockFileMaintenance` (Dependabot has no equivalent; `pnpm dedupe` stays a manual
step) and the `security` label on vulnerability PRs (security updates are switched on in the repository settings,
not in this file).

## pnpm catalogs (decides A5d)

Dependabot supports the pnpm `catalog:` protocol: it reads the catalogs in `pnpm-workspace.yaml` and bumps the
version there (dependabot-core #11418, enabled for everyone by #11477 in February 2025; catalog range resolution
#16049 and root-manifest specifier fix #16317 landed in September 2026). Open issues remain for multiple named
catalogs (#12445), lockfile specifiers (#12244, #14339) and the dependency type a catalog entry is grouped under
(#14824). A single default catalog avoids the first; the others are bot-side defects that show up in a PR diff
and do not block updates.

The supported pnpm versions listed in the GitHub docs are v7 to v10; check this before the pnpm 12 upgrade (A4k).

## Tests

`.github/dependabot.yml` parses as YAML. The real check is the first scheduled Monday run: Dependabot PRs appear
for each ecosystem.
