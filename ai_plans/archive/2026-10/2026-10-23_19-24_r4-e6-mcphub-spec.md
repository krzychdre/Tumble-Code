## Problem

"should handle connection type checks safely" wrapped every assertion in `if (type === "connected") ... else if
(type === "disconnected")`, so it passed whatever the connection state was. "should validate timeout values" parsed
`ServerConfigSchema` from `McpHub.spec.ts` with 0, 3601 and -1 (0 and -1 run the same check) and never touched the
inclusive edges.

## Change

- The tautological test is deleted.
- The timeout bounds are our contract: `BaseConfigSchema` in `mcpConfigSchema.ts` defines `timeout` as 1 to 3600
  seconds, and McpHub falls back to the 60 s default for a value outside it. They are tested where they are
  defined, in `mcpConfigSchema.spec.ts`, through `validateServerConfig`: one `it.each` accepts 1 and 3600, one
  rejects 0 and 3601. The `McpHub.spec.ts` copy and its `ServerConfigSchema` import are gone.
- `McpHub.spec.ts` 3738 lines before, 3654 after; `mcpConfigSchema.spec.ts` 81 before, 91 after.
