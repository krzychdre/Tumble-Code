## Bumped, with what each breaking section says about us

- `globals` 17: splits `audioWorklet` from `browser`; our ESLint configs use neither directly. The full turbo
  lint passes.
- `p-wait-for` 6 and 7: Node 20/22 floor, `customTimers` removed (not used), abort and timeout now settle while a
  `condition` is pending (a fix our callers only benefit from).
- `safe-stable-stringify` 3: the circular marker becomes `[Circular: N]`. `ToolRepetitionDetector` stringifies
  tool parameters parsed from JSON, which cannot be circular.
- `debounce` 3: pure ESM and default export only; `useScrollLifecycle.ts` uses the default import.
- `fuzzysort` 4: readonly result scores, `require()` support, exported types; our four autocomplete triggers
  only call `go(query, targets, options)`.
- `katex` 0.19 (both the webview copy that ships the stylesheet and the `rehype-katex` override, which
  `katex-styles.spec.tsx` keeps equal): missing character metrics go through `strict`; we pass no `strict`
  option, so the default `warn` applies.
- `@vscode/codicons` 0.0.46-24 (npm `latest`; pinned exactly because the version carries a prerelease suffix):
  every class of 0.0.36's `codicon.css` is still present (570 then, 746 now).
- `ovsx` 1.2.0 to 1.3.0 (a minor; drops its `@vscode/vsce` dependency, 1100 lockfile lines). `npx ovsx --version`
  prints 1.3.0.

## Deferred

- `@vscode/test-electron` 3 and `mocha` 12: mocha 12 is ESM-only (`"type": "module"`), and the e2e suite is
  compiled to CommonJS and `require`s it inside the VS Code test host. Only a real e2e run can prove it; they
  belong in their own branch with that run.
- `nock` 15: unmatched requests return a 501 response instead of throwing, `reply` callbacks receive a `Request`,
  `delayBody`/`delayConnection` are gone (migration guide `migrating_to_15.md`). `src/vitest.setup.ts` and five
  wire specs use it, so it needs its own branch.
- `serialize-error` 13: non-error values become a `NonError` whose message is `Non-error value: <value>`, so
  `handleValidationError("text")` in `services/code-index/shared/validation-helpers.ts` would report that prefix
  instead of the text. The serialization there adds nothing over reading the error's own properties; the fix is
  to drop the dependency, in its own branch.
- `@dotenvx/dotenvx` 2 (and 1.75 and later): it moves onto `@dotenvx/primitives` and `@dotenvx/providers`, which
  pull `systeminformation` and more into the extension bundle (`dist/extension.js` grew by about 2 MB in a trial
  build) for a loader of an optional development `.env`. The lockfile keeps 1.66.0.
- `google-auth-library` 11: only the Node 22 floor changes, but `@anthropic-ai/vertex-sdk` 1.1 and `@google/genai`
  still depend on ^10. Bumping our direct dependency alone bundles two copies and hands a v11 `GoogleAuth` to the
  v10-typed Vertex client. Wait until both move.
- `isbinaryfile` 6: `engines.node >= 24.0.0`; the extension and the CLI run on Node 22.
