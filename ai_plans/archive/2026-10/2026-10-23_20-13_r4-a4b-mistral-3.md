## Problem

The 3.0.0 breaking list (GitHub release v3.0.0 of mistralai/client-ts) is in surface we do not use (`Runs`,
`encode*`, beta connector and workflow records) except one item: `EventStream[Symbol.asyncIterator]` now returns
the `ReadableStream` iterator type instead of `AsyncIterableIterator`. `mistral.ts` consumes it with a plain
`for await`, which type-checks and runs the same.

3.x also adds a voice-agent transport that statically imports the optional peer `@livekit/rtc-node`; the module
is reached only through a dynamic import in `voice-agents/client.js`, but esbuild follows it and the bundle fails
with `Could not resolve "@livekit/rtc-node"`. Its tracing module now imports
`@opentelemetry/semantic-conventions/incubating`, which 3.x lists as a regular dependency, while our externals
still kept semantic-conventions out of the bundle for the 2.x tracing module.

## Change

- Bump to ^3.1.0.
- `extensionExternals`: `@livekit/rtc-node` becomes external (never loaded: we do not use voice agents);
  `@opentelemetry/semantic-conventions` is no longer external, so it is bundled like `@opentelemetry/api`.
  The VSIX has no `node_modules`, so any external that the SDK requires at load would break activation.

- `pnpm turbo run bundle --filter=tumble-code` succeeds. The bare `require("...")` calls of non-builtin modules
