## Problem

`@dotenvx/dotenvx` served three small jobs: reading the optional development `src/.env` at extension load, loading
`apps/vscode-e2e/.env.local` for `pnpm test:run`, and reading `RUN_TESTS_ON_PUSH` from a root `.env.local` in the
pre-push hook. From 1.72 it pulls systeminformation, conf, open and undici into `dist/extension.js` (+1.1 MB), so
Dependabot had to ignore it.

## Change

- Extension: `loadOptionalEnvFile` calls `process.loadEnvFile` (Node >= 20.12; the VS Code 1.102 host runs Node 22)
  only when the file exists, so a missing file stays silent as before.
- e2e: `node --env-file-if-exists=.env.local ./out/runTest.js` (Node >= 22.9; engines and CI are 22.23.3).
- pre-push: `RUN_TESTS_ON_PUSH=true`, from the environment or `.env.local`, runs `pnpm run test` with `.env.local`
  loaded, through a `node --env-file-if-exists` wrapper.
- Dependency, lockfile entries and the Dependabot ignore rule are removed.

Semantics match what we used from dotenvx: variables already in the environment are not overridden, `#` comments
and quoted values parse the same for our files (plain `KEY=value` lines, see `.env.local.sample`). The old
try/catch around the load is gone: Node's parser does not throw on content, and a missing file is checked first.

## Tests

- `src/utils/__tests__/fs.spec.ts` with a temp file: missing file is ignored; a present file sets a new variable
  (quoted value, comment line) and keeps a variable already set. Mutations: dropping the existence check fails the
  missing-file case; inverting it fails both cases.
- `extension.spec.ts`: the two dotenvx mock tests are removed (they asserted the mock call).
- Probe: `node --env-file-if-exists=.env.local probe.js` with and without the file, and the pre-push flag check with
  the flag in the file, in the environment, and absent.
- Bundle built: `src/dist/extension.js` contains no `dotenvx` or `systeminformation`.
- tsc, eslint, knip.
