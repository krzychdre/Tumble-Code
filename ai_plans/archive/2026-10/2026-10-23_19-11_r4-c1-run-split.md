# R4 C1: `run()` split into named steps

- **Status:** done
- **Related plans:** `ai_plans/2026-10-23_17-20_maintenance-audit-round-4.md` (item C1)

## Touched files

- `apps/cli/src/commands/cli/run.ts`

## Problem

`run()` was about 650 lines with some 40 locals: flag checks, settings, provider resolution, limits, provider
checks, host options, the TUI render and the print/JSON loop. The provider settings of a configuration
(`toProviderSettings({ ...config, apiKey: keyFor(config), reasoningEffort, modelSettings })`) were spelled three
times, and the "apiKeyEnv names X, but ..." message twice.

## Change

- `run()` (18 lines) sets the logger, decides TUI or print, calls `resolveRunOptions()` and then `runTui()` or
  `runPrint()`.
- `resolveRunOptions()` runs the steps in the original order (every message and exit unchanged and in the same
  sequence): `readPromptAndSession`, the clear screen, `loadRunSettings`, the "no provider configured" note,
  `resolveProviders`, `resolveRunLimits`, the host options, `checkProviders`, the per-mode provider settings, the
  workspace, output format and resume checks.
- `settingsFor(config)` (in `resolveProviders`) is the one place that builds provider settings; the base, the
  per-mode and the /model settings use it. `missingApiKeyEnvMessage` backs both missing-key messages.

  from the base configuration turn 10 red; restored.
