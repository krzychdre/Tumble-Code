# R4 A5d: one pnpm catalog for dependencies shared by several workspaces

**Status:** done.
**Related plans:** `2026-10-23_17-20_maintenance-audit-round-4.md` (item A5d),
`2026-10-23_18-55_r4-a1-dependabot.md` (Dependabot updates pnpm catalogs, which allowed this item).
**Touched files:** `pnpm-workspace.yaml`, `package.json`, every workspace `package.json` that declares a shared
dependency, `pnpm-lock.yaml`.

## Problem

27 dependencies were declared in two to twelve workspaces each (`vitest` and `@types/node` in 12, `zod` in 8,
`rimraf` in 5), some with drifted ranges (`zod` as `^4.6.5` and `4.6.5`, `execa` as `^9.5.2` and `^9.6.1`,
`globals` as `^16.0.0` and `^16.3.0`, `react` as `^19.3.0` and `19.3.0`). A bump had to touch every copy, and the
root kept `zod` and `typescript` overrides to hold the copies together.

## Change

- `pnpm-workspace.yaml` has a default `catalog:` with every dependency declared in two or more workspaces; each
  of those declarations says `"catalog:"`. Drifted ranges were unified on the higher one (`execa ^9.6.1`,
  `globals ^16.3.0`) or the stricter one (`zod 4.6.5`, `react 19.3.0`).
- The `zod` and `typescript` root overrides are gone: with one declaration each, removing them leaves every
  resolved version unchanged (only the peer range text recorded in the lockfile differs).
- `react` stays exact because the CLI bundles it and must render with the version development ran.
- Workspace-local dependencies (declared once) keep their range in their own `package.json`.

The release manifest of the CLI (`apps/cli/src/lib/utils/release-manifest.ts`) pins each external dependency to the
installed version, not the specifier, and the VSIX is packaged with `--no-dependencies`, so `catalog:` never
reaches an `npm install` outside pnpm.

## Tests

- `grep -rn '"vitest": "' --include=package.json . | grep -v catalog | grep -v node_modules` prints nothing.
- The resolved package set equals the one before the catalog except for duplicates that collapsed onto the
  unified ranges (`execa` 9.6.0, `globals` 16.1.0, `ignore` 7.0.4 and stale copies of `@vscode/vsce-sign*`,
  `@azure/*`, `@jridgewell/*`, `acorn`, `fdir`, `tinyglobby` and others); no package was added.
- `pnpm knip` exits 0; the pre-push hook runs `check-types` for every workspace.

## Notes

New workspaces that need one of these dependencies declare it as `"catalog:"`. A dependency becomes a catalog entry
when a second workspace starts declaring it.
