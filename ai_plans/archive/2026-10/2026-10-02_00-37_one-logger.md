## Problem

Measured on origin/main 648a50d56, production code in `src/core` (without `src/core/memory`), `src/activate`,
`src/utils`, `src/extension.ts`, `src/extension`, `src/services`, `src/integrations`, `src/api`:

| channel                                 | before |
| --------------------------------------- | ------ |
| `console.*` calls                       | 477    |
| `provider.log` and the `host.log` seams | 123    |
| `logger.*` calls                        | 54     |
| `appendLine` calls                      | 55     |

- In a packaged extension `console.*` goes to the extension host log, never to the Tumble Code output panel, so most
  diagnostics were invisible to a user debugging from the panel.
- `extension.ts` built two logger factories: `createLineLogger` (for `logger`) and
  `createDualLogger(createOutputChannelLogger(outputChannel))` (for the cloud package). `extension/api.ts` had a third
  copy of the same per-argument formatter.
- `ClineProvider.log` wrote to the channel and to `console.log`; `core/checkpoints/index.ts` wrapped it in a helper that
  also called `console.log`, so checkpoint lines reached the console twice.
- `CompactTransport` (sync `writeFileSync` to `./logs/app.log`) was reachable only from tests with `ROO_TEST_LOGS=1`.

## Fix

- `src/utils/logging/index.ts` is the only logger: `logger.debug/info/warn/error(...args)` formats like `console.log`
  (`util.formatWithOptions`, a lone string verbatim), `logger.scope(name)` adds `[name]`, and a trailing `{ ctx }`
  argument (the old `LogMeta` convention, still used by bedrock and `src/core/memory`) becomes the scope.
  `configureLogger({ appendLine, consoleLevel, debug })` sets the destination; `setDebugLogging` follows the setting.
- Activation configures it first: lines go to the output channel; `debug` lines only while `tumble-code.debug` is on
  (the same switch as the `[perf]` counters, re-read on change). The console gets a copy in a development host (all
  levels) and in the CLI (errors only; the CLI mutes the console except `console.error`, which it writes to
  `~/.roo/cli-debug.log`, so the TUI stays clean and errors keep reaching the debug log as before). In tests the
  logger is silent unless `ROO_TEST_LOGS=1`, which now prints to the console instead of writing a file.
- `ClineProvider.log`, the cloud package's log function, the Codex OAuth manager, the API's opt-in log, the network
  proxy, auto-import, the Roo Code migration and `getVisibleProviderOrLog` write through `logger`. The helpers that took
  an output channel only to log (`autoImportSettings`, `migrateFromRooCode`, `initializeNetworkProxy`,
  `getVisibleProviderOrLog`, `OpenAiCodexOAuthManager.initialize`) lost that parameter.
- `console.error` became `logger.error`, `console.warn` `logger.warn`, `console.debug` `logger.debug`, `console.log`
  and `console.info` `logger.info`, except per-request or per-chunk traces, which became `logger.debug`: terminal
  shell-execution events and the zsh temp-dir lines, message-manager cleanup lines, custom tool results, task dispose,
  stream abort lines, the checkpoint git environment lines, Qdrant indexing markers. Message text is unchanged.
- `no-console` is an ESLint error in `src/**/*.ts` outside tests and mocks, `src/shared`, `src/workers` and
  `src/i18n/setup.ts`.

After, same scope:

| channel                                 | after                                                             |
| --------------------------------------- | ----------------------------------------------------------------- |
| `console.*` calls                       | 1 (the `.env` load in `extension.ts`, before the logger exists)   |
| `provider.log` and the `host.log` seams | 122 (all now end in `logger.info`)                                |
| `logger.*` calls                        | 572                                                               |
| `appendLine` calls                      | 3 (the logger, its wiring, the ripgrep diagnostic report channel) |

## Exclusions

- `src/core/memory`: do-not-touch area; it already used `logger` and keeps its calls as they are.
- `src/workers/countTokens.ts`: runs in a workerpool thread where the logger is never configured.
- `src/shared/**`: bundled into the webview as well; it may not import extension code.
- `src/i18n/setup.ts`: loads translations at import time, before `activate()` configures the logger.
- The `.env` warning at the top of `extension.ts`: runs before the logger is configured (eslint-disable with reason).
- `src/services/ripgrep/diagnostic.ts`: its own "Ripgrep Diagnostic" channel shows a report on request; that is
  output, not logging.
- Scripts, tests and mocks. `packages/*` (for example `safeJsonParse` in `@roo-code/core`) still log to the console.

## Tests

- `src/utils/logging/__tests__/logger.spec.ts`: silent until configured, every level routed to the channel with its
  level, debug dropped unless enabled and following `setDebugLogging`, console-style formatting and verbatim lone
  strings, error stacks, scope and `{ ctx }`, console copy only from `consoleLevel` up, a scope created before
  configuration, a throwing channel.
- Specs that asserted on `console.*` or on the channel now assert on the same call on `logger` at the new level (for
  example `Task.dispose.test.ts` on `logger.debug`). `TaskLifecycle.abort-memory-writers.spec.ts` now counts the
  `[memory]` lines: the stub's other abort errors used to go to `console.error`, which the spy did not watch;
  now they share `logger.error`. `vertex-credentials.spec.ts` keeps a console spy for the JSON parse error, which comes from
  `@roo-code/core`. `extension.spec.ts` still checks the real lines in the mocked output channel.
- Run with `--maxWorkers=2`, batched by folder: `activate`, `utils`, `__tests__`, `extension`, `integrations`, `api`,
  `services`, `core` (without memory) and `core/memory`. All pass except three failures that also fail on origin/main
  (`registry.spec.ts` expects 139 handlers, two `Task.spec.ts` spill-policy tests).

## Notes and caveats

- Output panel lines change shape: `provider.log` lines used to be raw, now they carry the time and `[info]`.
- `provider.log` and the `log(message)` seams of the ClineProvider collaborators stay as thin wrappers; all their
  lines are `info`, including the few that report errors. Converting the 122 call sites to levelled `logger` calls is
  possible later but was left out to keep this change reviewable.
- The `tumble-code.debug` setting description still talks only about the debug buttons; it now also enables debug
  log lines (and, already before, the `[perf]` counters).
- Many specs keep spy variables named `consoleErrorSpy` and so on although they spy on `logger`.
