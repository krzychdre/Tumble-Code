## Change

- **One source for the pnpm version.** `pnpm/action-setup` v6.1.0 (which added pnpm 12 support) reads
  `packageManager` when `version` is omitted, so the composite action no longer carries its own default. No
  workflow passed `pnpm-version`. Locally an installed pnpm 10 or newer switches to the pinned version on its own
  (`manage-package-manager-versions`), corepack reads the same field, mise reads `.tool-versions`.
- **`allowBuilds`.** `@vscode/ripgrep` 1.18 has no install script any more (the binary comes from the
  `@vscode/ripgrep-<platform>-<arch>` optional package), so it needs no entry, and the composite action's
  `GITHUB_TOKEN` for its download went with it. pnpm 12 fails an install on build scripts nobody decided on
  (`ERR_PNPM_IGNORED_BUILDS`); the four packages it named (`@google/genai`, `@vscode/vsce-sign`, `esbuild`,
  `protobufjs`) are set to `false`, which is what pnpm 10 did with them silently.
- **`minimumReleaseAge`.** The built-in one-day default stays (no repo setting, so pnpm keeps it non-strict and
  the Dependabot traps around a repo-configured `minimumReleaseAge` and `devEngines.runtime` do not apply). Eight
  versions locked earlier today were younger than a day and failed the frozen install with
  `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`; they are excluded by exact `name@version`, which is narrower than
  relaxing the policy. The entries are harmless once the versions are a day old (2026-10-24T14:27Z at the latest)
  and can then be deleted.
- **`.npmrc`**: the repo has none, nothing to move. **`--frozen-lockfile false`**: not used anywhere.
- **`pnpm audit`**: pnpm 12 reports GHSA ids in `github_advisory_id` exactly like 10.8.1 did; the allowlist keys
  are GHSA ids already. Both versions report the same nine advisories for main's lockfile.
- `scripts/bootstrap.mjs` installs an unpinned `pnpm` only when none is present; that pnpm then switches to the
  pinned version, so it needs no change.
