# Dependency audit gate: accept an advisory only on its path, expire every entry, verify signatures

**Status:** done on `fix/sec-audit-gate`
**Related:** `private_docs/security-audit-2026-11-06/report.md` section 6 (P-4, P-5, P-15, PO-3)
**Touched:** `scripts/audit-gate.mjs`, `scripts/audit-allowlist.mjs`, `scripts/__tests__/audit-gate.test.mjs`,
`.github/workflows/dependency-audit.yml`

## Problems and causes

- **P-4.** `audit-gate.mjs` accepted an allowlisted GHSA id wherever it appeared. The entries' reasons are about one
  dependency chain ("only the zod 3 copy of @lmstudio/sdk"), so the same advisory arriving through a new, shipped
  dependency passed silently. Checking `module_name` (the report's suggestion) adds nothing: a GHSA id already names
  the package. What the reason covers is the path, which `pnpm audit --json` lists per finding
  (`src>@lmstudio/sdk>zod`).
- **P-5.** The expiry check sat inside the loop over reported advisories, so an entry whose advisory stopped being
  reported never expired.
- **P-15.** No workflow verified registry signatures.
- **PO-3.** The workflow ran `pnpm audit --prod --json` twice, once per script.

## Fix

- Each allowlist entry has `via`, the chain its reason covers (`@lmstudio/sdk`,
  `@mistralai/mistralai>@azure/identity`). The gate fails on every audit path of the advisory that does not contain
  `>via>`.
- Expiry is checked for every entry before the advisory loop.
- The gate logic is `auditProblems(report, allowlist, today)`, exported for the test; the CLI part reads stdin as
  before.
- The workflow writes one report to `$RUNNER_TEMP/audit.json` and feeds both scripts from it, then runs
  `pnpm audit signatures` as a blocking step. It reads the lockfile only (checked on a copy with no `node_modules`),
  so the job still skips the install; the tree is clean today (1577 packages verified, 17 s).

## Tests

`scripts/__tests__/audit-gate.test.mjs` (runs in code-qa's `node --test scripts/__tests__/*.test.mjs`): accepted
path, below-high ignored, unlisted high, allowlisted id on another path, expired entry with no advisory. Mutations:
accepting every path of a listed id turns the "another path" case red; skipping the expiry loop turns the "expired
entry" case red. The gate passes on today's real `pnpm audit --prod --json` report.
