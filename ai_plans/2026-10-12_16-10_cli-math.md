# CLI: math formulas (images in graphic terminals, Unicode text elsewhere)

Status: done on `feat/cli-math`

## Problem

The owner asked (2026-10-12, with a screenshot of an improper integral answer) for formulas to render in
the extension and in the CLI's graphic mode. The CLI's line-based Markdown renderer (`Markdown.tsx`) knew
no math at all: `$\int_{-\infty}^{0} ...$` and `$$...$$` reached the terminal as raw TeX.

## Design

- **Display math** (`$$...$$` or `\[...\]` filling a line, or opening a block that closes on a later line)
  becomes a `MathBlock`. Like `MermaidBlock`, it is an image in the printed scrollback of a terminal that
  draws images (kitty, iTerm2, sixel; see `cli-inline-images`) and text everywhere else: the live tail, a
  text-only terminal, a formula still streaming (no closing line yet), TeX that MathJax rejects.
- **Inline math** (`$...$` with Pandoc's rule, `\(...\)`, `$$...$$` or `\[...\]` inside a line) is text:
  an image cannot sit inside a line of text. Rendered italic.
- **Text form** `texToUnicode` (`ui/utils/texToUnicode.ts`): a small reader for TeX groups and commands.
  Greek, operators, relations, arrows, big operators; super/subscripts in Unicode when every character has
  a form, `^(...)` otherwise; vulgar fractions (`½`, `¾`) or `a/b`; `√`, `∛`; `\mathbb`; combining
  accents; `\text` as written; matrices as `( a b ; c d )`; an unknown command stays as written.
  The screenshot's integral reads `∫_(-∞)⁰ (3x³ + 6x + ½) dx`.
- **Image form** `renderMathImage` (`ui/graphics/math.ts`): MathJax 4 (`@mathjax/src`, font
  `@mathjax/mathjax-newcm-font`) TeX input + SVG output with `fontCache: "none"`, so glyphs are paths that
  resvg draws (KaTeX emits HTML+CSS, which resvg cannot). `currentColor` is replaced by the foreground
  `foregroundFor(background)` (shared with mermaid), and the size comes from the viewBox (thousandths of
  an em) with the em at 0.85 of a terminal row. Measured: 15-40 ms per formula; the screenshot's limit at a
  42 px row is 518 x 76 px, two rows.
- **Synchronous**: the transcript is printed once (`<Static>`), so the image must exist in the same
  render. MathJax 4 loads rarer glyph ranges (latin letters in `\text`, double-struck, calligraphic) on
  demand and throws a "retry" error without a loader; `mathjax.asyncLoad = require` with
  `asyncIsSynchronous = true` loads them inline (verified: `\text{(rozbieżna)}`, `\mathbb{R}`). The loader
  swallows failures, because MathJax would `console.warn` them over the TUI.
- **Lazy**: MathJax is loaded with `createRequire` on the first display formula, so startup does not pay
  for it. It stays an external dependency (in the release manifest), not bundled; knip is told so
  (`knip.jsonc`, it cannot see a `createRequire` string).
- **Prompt**: the CLI's TERMINAL DISPLAY section says to write math in TeX, `$$...$$` on a line of its own
  for a drawn formula (images) or that it shows as Unicode text (text terminals).

## Cost

`@mathjax/src` + font + their dependencies add about 105 MB to `node_modules` of the installed CLI
(today 131 MB in total). A slimmer option, if that matters later: bundle the MathJax core (about 1.7 MB)
and only the latin/greek/double-struck/calligraphic glyph ranges.

## Tests

- `utils/__tests__/texToUnicode.test.ts`: the screenshot's formulas and the conversion rules.
- `graphics/__tests__/math.test.ts`: colour and pixel size in the SVG, no `ex` units, errors give undefined.
- `graphics/__tests__/MathBlock.test.tsx`: image marker and kitty sequence in the scrollback; Unicode in
  the live tail and in a text terminal; `$$`/`\[` over lines and on one line; streaming formula as text;
  rejected TeX as text.
- `components/__tests__/Markdown.test.tsx`: inline math, and prices / `\[1\]` left as written.
  With `Markdown.tsx` from main, 11 of them fail.
- `terminal-display.spec.ts`: the math lines in both prompt variants.
