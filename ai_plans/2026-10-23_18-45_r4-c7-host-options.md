## Problem

- `extensionAPI` held the return value of `activate()` and was never read.
- `exitOnComplete` was a required host option that only the TUI hook read; `list.ts` had to set a meaningless `true`.
- `switchModel` had a fallback for a missing `resolveModelProviderSettings` (`withModel` plus the `models` entry
  and `forcedReasoningEffort`). The only production creator with per-mode settings (`run.ts`) always passes the
  resolver, so the fallback, `forcedReasoningEffort` and `withModel` ran only in tests.

## Change

- `extensionAPI` and `forcedReasoningEffort` are gone; `withModel` and its spec are deleted.
- `exitOnComplete` is a prop of `TUIAppProps` and `UseExtensionHostOptions`; the host never sees it.
- `switchModel` needs both `modeProviderSettings` and `resolveModelProviderSettings` and uses the resolver only.
- `integrationTest` stays: it is a test seam the audit lists, but the proposal keeps it.

## Tests

- `extension-host.test.ts` switch specs pass a small resolver; the fallback-only "keeps --reasoning-effort" spec
  moves to `run.test.ts` ("--reasoning-effort alone ...") as an assertion on the real resolver.
- Mutation: `reasoningEffort: undefined` in `run.ts`'s resolver turns the new assertion red; restored.
- `npx vitest run` on the touched specs plus `src/commands/cli/__tests__` and `src/ui/__tests__`: 426 green.
- `tsc --noEmit`, eslint on touched files, `pnpm knip`: clean.
