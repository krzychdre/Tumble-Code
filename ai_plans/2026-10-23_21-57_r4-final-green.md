## Problem

Round 4 landed as about 75 pull requests merged without waiting for CI. Running every suite once on the result
showed three defects:

1. The CLI integration suite failed 0/4 with "Could not find ripgrep binary". `@vscode/ripgrep` 1.18 (#974) no
   longer downloads `rg` into `@vscode/ripgrep/bin`; it ships the binary in a per-platform optional package
   (`@vscode/ripgrep-linux-x64/bin/rg`). Under pnpm that package is linked next to `@vscode/ripgrep` inside
   `node_modules/.pnpm`, not under `apps/cli/node_modules`, so neither the extension's lookup (appRoot = CLI root)
   nor `tumble doctor` finds it, and `apps/cli/scripts/build.sh` and `cli-release.yml` (`find -path
"*/@vscode/ripgrep/bin/rg"`) would ship a release without ripgrep.
2. `pnpm vsix` failed with "Failed to parse semver of @types/vscode": `vsce package` checks the `@types/vscode`
   range against `engines.vscode` and cannot read `"catalog:"` (#937). CI never packages on a pull request, so only
   a publish would have hit it.
3. `autoDream.spec.ts` MEM-3 failed under load: the test slept 10 ms and expected the runner to have been called,
   but the dream reads the memory files first. The MEM-2 abort test had the same 10 ms wait (the abort listener
   exists only once the runner runs). This is the known Windows timing flake. Also, the MEM-3 test never reached the
   re-entry guard: the 10-minute scan throttle stopped the second call first.

## Change

1. `apps/cli` pins `@vscode/ripgrep` to `~1.17.1` and `allowBuilds` lets its postinstall download `rg`, the state
   before #974. Moving to 1.18 is a follow-up in the audit doc (lookup, doctor, build and release scripts).
2. `src/package.json` spells `"@types/vscode": "^1.102.0"`; the catalog entry stays for the other two workspaces,
   with a comment saying why `src` is the exception.
3. The autoDream tests wait on conditions: `await executeAutoDream` (it returns once the dream is registered),
   `vi.waitFor` on the runner, `drainPendingDreams` instead of the trailing sleeps. The MEM-3 test moves the clock
   past the scan throttle before the second call.
