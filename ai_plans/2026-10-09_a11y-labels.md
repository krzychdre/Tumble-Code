## What changed per screen

### Mode popover (ModeSelector)

- The list is split into two groups, "Built-in" and "Custom", each with a small uppercase label
  (`text-[length:var(--text-meta)] uppercase tracking-wide text-vscode-descriptionForeground`, the same
  `mx-1 px-2.5` inset as the rows), as in the "Popovers" proposal of the demo page.
- The groups appear only when both have entries and the search box is empty. While searching, the list stays one
  flat list in relevance order.
- A mode counts as custom when its slug is in `customModes`, also when it overrides a built-in slug. This is the
  rule the Modes view uses (`findModeBySlug(slug, customModes)`). `getAllModes` keeps such an override at the
  built-in position, so grouping moves it into the Custom group, after the built-ins. The rendered order is the
  order of the groups, so the visual order and the Tab order are the same.
- Each group is `role="group"` with `aria-labelledby` pointing at its label; labels are plain text and not
  focusable.
- The rows were clickable `div`s that the keyboard could not reach. They are now `<button type="button">` with
  `aria-pressed` for the current mode and the focus ring. Same click handler, same test id.

### Create worktree dialog

- The "browse folder" icon was a clickable SVG. It is now a `<button type="button">` with
  `aria-label={t("worktrees:browseFolder")}`, a `StandardTooltip` with the same text, the focus ring, and the same
  `browseForWorktreePath` message. It sits right after the path input in the Tab order.
