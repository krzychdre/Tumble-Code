## Security

### DEF-S1 Command auto-approval bypass through escaped quotes [V]

**Reproduction (run 2026-09-24 with tsx against the live tree):**

```text
command : echo \' && rm -rf /tmp/x \'
parsed  : {"commands":["echo ' && rm -rf /tmp/x \\'"],"parseError":null}
decision: auto_approve        (allow list ["echo"], deny list ["rm"])
control : echo hi && rm -rf /tmp/x   ->  auto_deny
```

Bash tokenizes the first command as `echo '` `&&` `rm -rf /tmp/x '`, so the denied `rm` runs. Cause: the regex quote
engine in `src/shared/parse-command.ts:632-639` ignores backslashes, while the state-machine scanner at `:209-213`
treats `\'` as a literal. A model steered by text it read (prompt injection) can run commands the user denied.

**Tests first:** a table in `src/shared/__tests__/parse-command.spec.ts` (66 cases today, none with escaped quotes
outside quotes) and `src/core/auto-approval/__tests__/commands.spec.ts` (26): `\'`, `\"`, `\\'`, `$'..'`, escaped
quotes adjacent to `&&`, `;`, `|`, `$(...)`, backticks. Every case asserts that the split matches bash's
tokenization.

**Fix:** a single quote-aware scanner used for both splitting and validation; when the scanner cannot prove a
clean split, the decision is `ask`, never `auto_approve`.
