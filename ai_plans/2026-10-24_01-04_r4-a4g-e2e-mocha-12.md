## Problem

`mocha` 11 pulls `serialize-javascript` 6 (high advisory: RCE via `RegExp.flags`, plus a moderate DoS) and `diff` 5
(low DoS). Both are dev-only, reachable only through `apps/vscode-e2e>mocha`. `mocha` 12 depends on
`serialize-javascript` ^7.1.1 and `diff` ^9, but ships as an ES module (`"type": "module"`), while the e2e suite
compiles to CommonJS and `src/suite/index.ts` loads Mocha with `import Mocha from "mocha"` (a `require`).

## Change

Only the two version bumps. No runner change is needed: the VS Code 1.102 extension host runs on Electron's
Node 22, where `require()` of a synchronous ES module is enabled by default, so the compiled CommonJS
`out/suite/index.js` still loads mocha 12 and the test files stay CommonJS. `@vscode/test-electron` 3 changes no
API we use (the major is the Node 22 engine; it adds optional `stdout`/`stderr` streams to `runTests`).
