The rules (one design language for the whole webview)

  1. Frame = 13% of the theme foreground; hover frame = 26%; surface fill 3%, hover 6%. Used by every card, block, popover section, chip and list. Replaces 8 border sources in use today (panel-border, dropdown-border, input-border with transparent fallback, editorGroup-border, widget-border, lineHighlightBorder, sideBar-background used as a border, hard-coded white rgba).
  2. Form controls (input, select, textarea, secondary button) use the 26% frame so they read as controls; checkbox and toggle use 45% so their outline meets the WCAG 3:1 contrast rule for small controls.
  3. Two heights only: 26px for form controls and buttons, 22px for compact toolbar chips and icon buttons. Today 18, 20, 22, 24, 26, 28, 32, 36, 40 and 48px are all in use.
  4. One focus ring: 1px theme focus colour, 1px offset, on every interactive element (today four different styles, and several elements have none).
  5. One selected state: focus colour at 18% fill (+ a 2px bar in side navigation). One hover: surface 6%.
  6. No text dimmed with opacity: secondary text uses the theme description colour. No hover-only controls: copy, docs and chevrons stay visible (keyboard and touch users never see hover-only buttons).
  7. No hard-coded colours: white rgba hovers, #757575 placeholder, #3c3c3c checkbox fallback, cyan checkpoint gradient, black overlay all derive from the theme.
  8. Kept on purpose: square corners (toggle above to compare), the orange frame accent for elevated auto-approve, the 2px status edge on tool blocks.
