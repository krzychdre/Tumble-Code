# UI step 5b: todo list (§2.8 of 2026-09-27_ui-modernization.md)

Branch `feat/ui-5b-todo`, off `origin/main` (19d6d7dc7), independent of 5a (no shared files: the ChatRow golden
stubs `UpdateTodoListToolBlock`, and no locale keys were added).

## What

- `chat/TodoListDisplay.tsx` (the list under the task header):
    - The header is a `<button type="button">` with `aria-expanded` and `aria-controls` pointing at the list
      (`useId`), keyboard focusable with the shared `focus-ring`.
    - Next to the `3/7` count, a 40px wide, 3px tall `role="progressbar"` (`aria-valuenow`, `aria-valuemin`,
      `aria-valuemax`, `aria-label` = the existing `chat:todo.partial` text), same track colour as the context
      bar (§2.4), filled with `--status-done`. The count and bar show in both states (the count used to show only
      while collapsed and unfinished), at `--text-meta` with tabular numerals.
    - Uses `useTranslation()` instead of the bare `i18next` `t`.
- `chat/UpdateTodoListToolBlock.tsx`: all 32 inline style objects replaced by classes. Hard-coded colours
  (`#fff`, `#333`, `#bbb`, `#888`, `#eee`, `#f14c4c`) replaced by theme colours: the delete confirmation uses
  the hover-widget colours and the delete button `errorForeground`. Status dots carry `data-todo-status`.
  Buttons got `type="button"`, the edit toggle `aria-pressed`, the remove button an accessible name, the
  confirmation `role="alertdialog"` labelled by its text.

## Why

The header was a clickable `div` (unreachable with Tab), the only progress cue was the bare count, and the tool
block's inline styles ignored the theme (a white dialog in dark themes) and could not be reached by the
density tokens or the radius clean-up.

## Deviations

- The block's English strings ("Todo List Updated", "Edit", "Add", the confirmation text...) stay hard-coded;
  moving them to i18n is a separate item. The spec asserts on those texts.
- The progress fill keeps one inline `width` (a computed percentage), the same way the context bar does.
